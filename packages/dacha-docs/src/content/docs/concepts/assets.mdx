An asset is a reusable entry in the `assets` section of the [configuration](/concepts/configuration/).
Each asset has an `id`, a `name`, a `kind` and `data`:

```json
{
  "id": "6b1e…",
  "name": "hero",
  "kind": "texture",
  "data": { "src": "images/hero.png" }
}
```

## Kinds of assets

The `kind` names the class that describes the asset. There are two families of kinds.

- **Media** kinds point to a file. The engine has three: `texture`, `audio` and `bitmapFont`.
- **Data** kinds hold only fields. Use them for things that are not actors, such as items,
  quests or lines of dialogue.

## Loading

Only media assets load. A data asset is ready when the game starts.

Put an asset id in an `asset` field and the engine
loads it for you. It loads the files before the scene starts. It unloads them when it destroys
the scene. The assets in the options of a world system stay loaded until the game ends.

An `asset` field is a field that the editor shows as a list of the project's assets. The
built-in components already have them, such as the texture of a sprite. In your own component,
behavior or system, declare one with `@DefineField`:

```ts
@DefineField({ type: 'asset', kind: 'audio' }) hitSound!: string;
```

See [inspector fields](/game-code/inspector-fields/#choosing-the-widget) for the other options.

If your code uses an id that no field holds, load the asset yourself. See
[Loading assets from code](#loading-assets-from-code).

## Reading an asset in code

Game code gets the project's assets as `assets`. Ask it for an asset by its class and id:

```ts
import { Texture } from 'dacha';

const texture = this.assets.get(Texture, sprite.texture);
texture?.resource; // the loaded texture, or undefined
```

A data asset has its fields right away. A media asset gives its file as `resource`. It is
`undefined` until the file loads.

## Your own kinds

A data kind extends `Asset`. Describe its fields with `@DefineField`, as you do in a component:

```ts
import { Asset, DefineAsset, DefineField } from 'dacha';

@DefineAsset({ name: 'item' })
export default class Item extends Asset {
  @DefineField() title!: string;
  @DefineField({ initialValue: 1 }) maxStack!: number;
  @DefineField({ type: 'asset', kind: 'texture' }) icon!: string;
}
```

A media kind extends `MediaAsset`. It fetches its file and returns the resource in
`fetchResource`. If the resource needs cleanup, free it in `disposeResource`:

```ts
import { MediaAsset, DefineAsset, DefineField } from 'dacha';

@DefineAsset({ name: 'levelMap' })
export default class LevelMap extends MediaAsset<LevelData> {
  @DefineField({ type: 'file', extensions: ['json'] }) src!: string;

  protected async fetchResource(): Promise<LevelData> {
    const response = await fetch(this.src);
    return response.json();
  }
}
```

Pass your kinds to the engine in `assets`, next to the built-in ones. The editor finds them in
files that end with `.asset.ts`. See [auto-registration](/game-code/auto-registration/).

## Loading assets from code

You need this section only when your code uses an asset id or a template id directly. If the id
comes from a field, the engine loads it for you.

The engine does not know about such an id. A template that you spawn by it loads its assets only
when the actor first needs them. The sprite draws nothing for a few frames, and the first sound
does not play.

To load one asset, call `load()` and wait for it:

```ts
import { Audio } from 'dacha';

const buffer = await this.assets.get(Audio, soundId)?.load();
```

The engine does not track an asset you load this way. If a scene also uses it, the asset
unloads with that scene. To keep an asset loaded, hold it with `acquire`.

To hold a set of assets and templates for some time, call `acquire` with an owner and the ids.
`acquire` resolves when the files are ready. Call `release` with the same owner when you no
longer need them. The engine unloads an asset when nothing uses it. This scene system holds
the assets for its scene:

```ts
async onSceneLoad() {
  await this.assets.acquire(this, { assets: [cutsceneId], templates: [bossId] });
}

onSceneDestroy() {
  this.assets.release(this);
}
```

The owner is an object, such as a system or a behavior, or a string.
A second `acquire` with the same owner replaces what the owner holds, so pass
all ids in one call.

A world system lives across scenes. In a world system, use a separate owner key for each
scene, not `this`.

`CharacterController` moves characters. You set the velocity of a character, and the controller
moves it as far as the world allows:

- It stops the character at walls, and slides it along them.
- It keeps the character on the ground on slopes and small steps down.
- It tells you whether the character stands on the ground, touches a wall, or hits a ceiling.

A character is not a `dynamic` body. Gravity, forces and collisions do not move it. It moves only
by the velocity you give it, so the controls stay exact.

The controller uses [physics queries](/systems/physics/queries/) to find obstacles. It needs
`PhysicsSystem`.

## Setting it up

The [starter project](/getting-started/installation/) does not include the character controller.
To add it:

1. [Set up physics](/systems/physics/#setting-it-up).
2. In the Systems tab, add *Character Controller*.
3. Add `CharacterController` and `CharacterBody` to the engine in `src/index.ts`:

   ```ts
   import {
     Engine,
     PhysicsSystem,
     CharacterController,
     Transform,
     Collider,
     RigidBody,
     CharacterBody,
   } from 'dacha';

   const engine = new Engine({
     config,
     systems: [CharacterController, PhysicsSystem, ...gameSystems],
     components: [Transform, Collider, RigidBody, CharacterBody, ...gameComponents],
     assets: [],
   });
   ```

4. Give the character actor three components:
   - `CharacterBody`,
   - a `Collider` with the type `box`, `circle` or `capsule`,
   - a `RigidBody` with the type `kinematic`.

The controller skips an actor whose `RigidBody` is not `kinematic`, with no warning. A `segment`
collider does not work either, because the controller cannot cast it. The character then passes
through everything.

### Order in the systems list

The controller works in `fixedUpdate`. Put it:

- after the systems that set the velocity of characters,
- before `PhysicsSystem`.

## Moving a character

`CharacterBody.velocity` is the velocity in world units per second. The controller moves the
character by it in every step. The velocity stays until you change it.

The controller does not add gravity. For a platformer, add it to the velocity yourself. This
system moves a player left and right, makes it fall, and makes it jump:

```ts
import { SceneSystem, ActorQuery, CharacterBody } from 'dacha';
import type { SceneSystemOptions, Time } from 'dacha';
import { DefineSystem } from 'dacha-workbench/decorators';

import Player from '../components/player.component';

const GRAVITY = 1500;

@DefineSystem({
  name: 'PlayerMovementSystem',
})
export default class PlayerMovementSystem extends SceneSystem {
  private time: Time;
  private actorQuery: ActorQuery;

  constructor(options: SceneSystemOptions) {
    super();

    this.time = options.time;
    this.actorQuery = new ActorQuery({
      scene: options.scene,
      filter: [CharacterBody, Player],
    });
  }

  fixedUpdate(): void {
    const { fixedDeltaTime } = this.time;

    this.actorQuery.getActors().forEach((actor) => {
      const body = actor.getComponent(CharacterBody);
      const player = actor.getComponent(Player);

      body.velocity.x = player.directionX * player.speed;

      if (body.onGround) {
        body.velocity.y = player.jumpRequested ? -player.jumpSpeed : 0;
      }

      if (body.onCeiling && body.velocity.y < 0) {
        body.velocity.y = 0;
      }

      body.velocity.y += GRAVITY * fixedDeltaTime;

      player.jumpRequested = false;
    });
  }
}
```

The y axis points down, so a jump has a negative velocity.

Reset `velocity.y` when the character stands on the ground. Otherwise gravity keeps adding to it,
and the character falls very fast from the next edge.

### Moving by a distance

`move(displacement)` moves the character by a distance, once. The controller adds it to the
movement of the next step, and then forgets it:

```ts
body.move(new Vector(4, 0));
```

The distance is in world units. It is not multiplied by the step time. Use `move` for a knockback,
or to carry a character on a moving platform.

## Character state

After each step, `CharacterBody` holds the result:

| Field | What it holds |
| --- | --- |
| `onGround` | The character stands on ground it can walk on |
| `onWall` | The character hit a wall in this step |
| `onCeiling` | The character hit a ceiling in this step |
| `groundNormal` | The direction out of the ground, when `onGround` is `true` |
| `groundActor` | The actor the character stands on, or `null` |

### Ground, walls and ceilings

The controller sorts every surface the character hits by its angle to `upDirection`:

- A surface that faces up, and slopes less than `maxSlopeAngle`, is **ground**.
- A surface that faces down in the same way is a **ceiling**.
- Everything else is a **wall**.

On ground, the character moves along the slope. At a wall, it slides along the wall.

## Settings

| Field | Default | What it does |
| --- | --- | --- |
| `motionMode` | `surface` | `surface` sorts hits into ground, walls and ceilings, and keeps the character on the ground. `free` treats every hit as a wall |
| `upDirection` | `{ x: 0, y: -1 }` | The direction that counts as up |
| `maxSlopeAngle` | `45` | The steepest ground the character can stand on, in degrees |
| `groundSnapDistance` | `1` | How far down the controller looks for ground, in world units |
| `skinWidth` | `0.1` | The small gap the controller keeps between the character and obstacles, in world units |
| `maxSlides` | `4` | How many times in one step the character can hit something and slide on |
| `maxRecoveries` | `3` | How many times the controller tries to push the character out of an overlap |
| `disabled` | `false` | Turns the controller off for this character |

The editor shows `upDirection`, `maxSlopeAngle` and `groundSnapDistance` only in the `surface` mode.

Use `surface` for platformers, and `free` for top-down games, where there is no ground.

`groundSnapDistance` keeps the character on the ground when it walks down a slope or a small step.
The character does not leave the ground on every bump. A larger value keeps it on the ground over
larger steps.

The editor and the configuration set `maxSlopeAngle` in degrees. In code, the field holds radians.

`upDirection` must not be `{ x: 0, y: 0 }`. The component throws when it gets a zero direction.

## What stops a character

The controller stops a character at an actor that has an enabled `RigidBody` of any type:

- `static` and `kinematic` bodies stop the character.
- A `dynamic` body stops the character like a wall.
- A trigger, a collider without a body, does not stop it.
- A disabled body does not stop it.

The controller uses the [collision layer](/systems/physics/collisions/#collision-layers) of the
character's collider. A character passes through colliders on layers that do not collide with
its layer.

### One-way bodies

The controller handles [one-way bodies](/systems/physics/bodies-and-colliders/#one-way-bodies)
itself. A platform with `oneWayNormal` `{ x: 0, y: -1 }` stops a character that lands on it from
above. A character that jumps from below passes through, and keeps passing through until it is
out of the platform.

## Overlaps

A character can start inside an obstacle. For example, a level places it too low, or you move it
through its `Transform`. The controller then pushes it out before it moves.

The controller does this when the character appears. After you move a character through its
`Transform`, call `recover()`:

```ts
transform.world.position.x = spawn.x;
transform.world.position.y = spawn.y;

body.recover();
```

The controller pushes the character out of `static` and `kinematic` bodies. It does not push it
out of `dynamic` bodies. With `maxRecoveries` set to `0`, it does not push the character out at
all.

## The CharacterHit event

Each time the character hits something while it moves, the controller sends `CharacterHit` to the
character's actor:

```ts
import { CharacterHit } from 'dacha/events';
import type { CharacterHitEvent } from 'dacha/events';

actor.addEventListener(CharacterHit, (event: CharacterHitEvent) => {
  if (event.kind === 'ceiling') {
    // play a bump sound
  }
});
```

| Field | What it holds |
| --- | --- |
| `actor` | The actor the character hit |
| `kind` | `ground`, `wall` or `ceiling`. In the `free` mode, always `wall` |
| `point` | The hit point, in world space |
| `normal` | The direction from the hit surface to the character |
| `distance` | How far the character moved before the hit |

One step can send several `CharacterHit` events, one for each slide. A character with zero velocity
gets no events. A character that gets gravity on the ground, as in the example above, hits the
ground in every step, so it gets a `ground` event in every step. To know that the character stands
on something, read `onGround`.

Like other events, `CharacterHit` arrives at the start of the next frame. See [delivery happens on
the next frame](/concepts/events/#delivery-happens-on-the-next-frame).

`CharacterHit` does not replace collision events. A character with a `kinematic` body also gets
[collision events](/systems/physics/collisions/), for example from triggers.

## Moving platforms

A character does not ride a moving platform by itself. When the platform moves, the character
stays where it is.

To carry the character, read `groundActor`. If it is a platform, move the character by the
distance the platform moved in this step, with `move`.

## Smooth movement

The controller moves characters in `fixedUpdate`. On a screen with a higher refresh rate than the
fixed step, the movement can look uneven. Add [Interpolation](/systems/interpolation/) to the
character to smooth it.

A template is a reusable actor definition. Place a hundred instances of one template, change
the template once, and all hundred change with it. A hundred copied actors give you none of
that.

A template is also the only way to create an actor while the game runs.

## Creating a template

Templates have their own tab in the explorer. *Add New Template* creates one with a
`Transform` and nothing else, exactly like a new actor. Rename it in the inspector, then give
it the components every instance should have.

The editor has no action that turns an actor already in a scene into a template. Build the
template first, then place instances of it.

## Templates nest

A template can hold child templates, and *Add New Template* puts one under the selected
template. The children are part of the definition, so placing the parent places the whole
branch as one actor with children.

Adding a child to a template that already has instances adds a matching child to every one of
those instances.

## Placing instances

The template tool places instances. Select it in the toolbar, pick the template to place, then
click in the viewport. The tool starts on the first template in the tree, so check which one it
will place before you click.

The tool shows two options beside the template picker:

- **Snap to Grid** aligns the new actor to the grid by its bounds, not by its origin, so
  tiles meet edge to edge.
- **Nesting** makes the new instance a child of the selected actor instead of a top-level
  actor of the scene. The position you clicked is converted into the parent's space, so the
  instance lands where you clicked.

## What an instance stores

An instance is an ordinary actor with a link to its template. It stores almost nothing of its
own. Placing one writes a single component: a copy of the template's `Transform` with the
position you clicked. Everything else comes from the template.

The component list under that field is the set of overrides, so a fresh instance shows only a
`Transform`.

## Overriding a component

When the engine builds an instance, it applies the template's components first and the
instance's components second. A component on the instance therefore replaces the template's
component of that name completely. Overrides work per component, not per field.

<TemplateOverrides />

*Add Component* on the instance creates such an override. It starts from the component's
default values rather than from the template's, so retype the values you want to keep.

## Changing a template

Edit a template and every instance follows, in the viewport as you type. An instance only
ignores the change if it overrides that component.

Deleting a template removes every instance of it from every scene, and the instances of its
child templates with them. One undo brings all of it back, because the editor records the
deletion and the cleanup as a single operation.

## Spawning at runtime

Bullets and enemies are not placed by hand. A system or a behavior spawns them from a template
while the game runs, and it addresses the template by id:

```ts
const bullet = this.actorSpawner.spawn(BULLET_TEMPLATE_ID);
```

Select the template in the explorer and use the copy button in the inspector header to get
that id. [Creating and destroying actors](/concepts/actors/#creating-and-destroying-actors)
covers what to do with the actor once you have it.

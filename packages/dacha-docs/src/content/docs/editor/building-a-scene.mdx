Scene building is the editor's main job. You create scenes, fill them with actors, arrange
those actors into a hierarchy, and move them until the level looks right.

## The start scene

The engine needs to know which scene to load first. You choose it in the inspector's Project
settings tab, in the `Start Scene` field.

## Adding actors

There are three ways to put an actor into a scene:

- **Empty.** *Add New Actor* creates an actor with only a `Transform`. With an actor selected,
  the new actor becomes its child.
- **From a template.** The template tool places an instance where you click. See
  [Templates](/editor/templates/).
- **From another actor.** Copy an actor and paste it. The copy gets its own id.

## The hierarchy

A child's `Transform` is measured from its parent, so moving the parent moves the whole
branch. Drag a node in the tree onto another node to change its parent.

## Moving actors

With the pointer tool, drag actors in the viewport. Hold <kbd>Shift</kbd> and click to select
several. A drag writes the new `offset` into the actor's `Transform`.

*Snap to Grid* in the toolbar moves the actor in grid steps.

The viewport edits position only. Type rotation and scale into the `Transform` component.

## Undo

Every change can be undone, up to the last 100 operations. Modal editors, such as the
animation editor, keep their own history.

The history lives in memory. Reloading the editor clears it, and so does a rebuild that
[repairs the configuration](/editor/generating-scripts/#after-create).

## Saving

<kbd>Ctrl</kbd>/<kbd>Cmd</kbd> + <kbd>S</kbd> writes the project configuration to the file
named by `projectConfig` in [dacha-workbench.config.cjs](/editor/config-reference/). In the
[starter project](/getting-started/installation/) that file is `data/data.json`, and autosave
is on.

Nothing reaches the running game until the file is written. Then the page reloads and the game
restarts from the start scene. [How it works](/introduction/how-it-works/) covers that loop.

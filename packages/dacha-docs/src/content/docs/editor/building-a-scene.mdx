Scene building is the editor's main job. You create scenes, fill them with actors, arrange
those actors into a hierarchy, and move them until the level looks right.

## Scenes

The Scenes tab of the explorer lists every scene in the project. *Add New Scene* adds one,
called `Scene` until you rename it in the inspector's `Name` field. Selecting a scene opens it
in the viewport.

Switching scenes moves the [editor's own
view](/editor/interface-tour/#the-viewport-runs-the-engine) back to the origin and resets its
zoom.

## The start scene

The engine needs to know which scene to load first. That choice is not part of the scene tree.
It lives in the inspector's Project settings tab, in the `Start Scene` field.

## Adding actors

There are three ways to put an actor into a scene:

- **Empty.** *Add New Actor* in the action bar creates an actor with a `Transform` and
  nothing else. Add the components it needs in the inspector.
- **From a template.** The template tool places an instance of an existing template where you
  click. [Templates](/editor/templates/) covers it.
- **From another actor.** Copy an actor and paste it. The copy is a separate actor, with its
  own id.

*Add New Actor* acts on the selection. With a scene selected the new actor goes into that
scene. With an actor selected it becomes a child of that actor.

## The hierarchy

Actors nest, and a child follows its parent. The `offset` in a child's `Transform` is measured
from its parent, so moving the parent moves the whole branch. Rotation and scale compose the
same way.

Drag a node in the tree to change its parent. The dragged actors become children of the node
you drop them on. Drop them on a scene and they become top-level actors of that scene. You
cannot reorder actors among their siblings this way, and dragging does not expand a branch.
Double-click a branch to expand it.

## Selecting actors

Click an actor in the tree or in the viewport. It is one selection either way, so the tree
highlights what you picked in the viewport, and the inspector fills with it.

The editor works with several actors at once:

- In the tree, hold <kbd>Ctrl</kbd> or <kbd>Cmd</kbd> to add single actors to the selection,
  or <kbd>Shift</kbd> to take a range.
- In the viewport, hold <kbd>Shift</kbd> and click to add an actor or remove it again.
- Clicking empty space clears the selection.

## Moving actors

With the pointer tool active, drag a selected actor to move it. The rest of the selection moves
with it. Every drag writes the new `offset` into the actor's `Transform`, which is the same
field you can type into by hand.

*Snap to Grid* in the toolbar rounds the drag to the grid step, which you change in the [grid
settings](/editor/interface-tour/#settings). The bottom bar reports the cursor position and the
grid cell under it while you drag.

## Copy, cut, paste and delete

The action bar, the Edit menu and the usual shortcuts all do the same four things. They act on
the current selection, and on the panel you are working in.

Paste needs a destination. It uses the selection: pasting with an actor selected puts the copy
under that actor, and pasting with a scene selected puts it into the scene. Pasting an actor
with nothing selected does nothing, because the tree's root contains scenes, not actors.

A copy is a new actor. The editor gives it a fresh id and, if the name is taken, a unique
name. Cut and paste moves the original instead of duplicating it.

## Undo

Every change goes through a command, so everything on this page can be undone with
<kbd>Ctrl</kbd>/<kbd>Cmd</kbd> + <kbd>Z</kbd>, and redone with <kbd>Shift</kbd> added. The
editor keeps the last 100 operations. Modal editors, such as the animation editor, keep their
own history, so undo inside one of them leaves the scene alone.

The history is kept in memory. Reloading the editor starts it empty, and so does a rebuild
that [repairs the configuration](/editor/generating-scripts/#after-create).

## Saving

<kbd>Ctrl</kbd>/<kbd>Cmd</kbd> + <kbd>S</kbd> writes the whole project configuration to the
file named by `projectConfig` in
[dacha-workbench.config.cjs](/editor/config-reference/). In the
[starter project](/getting-started/installation/) that file is `data/data.json`.

The starter project also turns autosave on, which saves every ten seconds. Both the switch and
the interval are keys in the same configuration file.

Nothing reaches the running game until the file is written. The page then reloads and the game
restarts from the start scene, so a run in progress is lost on every save. [How it
works](/introduction/how-it-works/) covers that loop.

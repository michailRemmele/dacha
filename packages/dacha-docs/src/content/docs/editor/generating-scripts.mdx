The editor can write a new class into your project: a component, a system, a behavior, a
shader or a filter effect. You get a file that compiles, with the import, the decorator and
the class already in place.

The file works in both the game and the editor because of [how scripts are
found](/game-code/auto-registration/). This page covers the editor half.

## Where to find it

There is no menu item for it. *Create New* is part of the picker for the thing you are adding,
so you create a class from the place you were about to use it:

| To create | Open |
| --- | --- |
| A component | *Add Component*, under an actor or template |
| A system | *Add System*, in the Systems tab |
| A behavior | *Add Behavior*, inside the `Behaviors` component |
| A filter effect | *Filter Effects*, in the `Renderer` system's options |
| A shader | *Material*, inside the `Mesh` component |

The class is not added to the actor or the list when it is created. Create it, then pick it
from the same list.

Type the class name the way you would write it in code. The editor derives the rest from it:
a directory in kebab case, and a filename of that same kebab case plus the suffix for the kind
of class. `MyCustomComponent` becomes
`my-custom-component/my-custom-component.component.ts`.

`Base Directory` starts at the `contextRoot` from your
[editor configuration](/editor/config-reference/) plus the plural of the kind, which gives
`./src/components` for a component. Change it and the editor remembers your choice for that
kind of class.

Tick `Customize Path` to type the subdirectory and the filename yourself. Clearing the tick
puts both back to what the class name implies.

Two things the dialog does not do: it does not check that the name is a valid class name, and
it does not warn you when the file already exists. An existing file is overwritten. Missing
directories are created.

## What you get

The generated file is a working example, not an empty shell. A component arrives with
one decorated field, so it has something to show in the inspector:

```ts
import { Component } from 'dacha';
import { DefineComponent, DefineField } from 'dacha-workbench/decorators';

interface MyCustomComponentConfig {
  exampleField: string
}

@DefineComponent({
  name: 'MyCustomComponent',
})
export default class MyCustomComponent extends Component {
  @DefineField()
  exampleField: string;

  constructor(config: MyCustomComponentConfig) {
    super();

    const { exampleField } = config;

    this.exampleField = exampleField;
  }
}
```

A system arrives as a `SceneSystem` whose `update` writes to the console, and a behavior
arrives the same way. Change the base class to `WorldSystem` if the system should outlive scene
changes.

The editor writes the file once and does not track it afterwards. Rename it, move it or
rewrite it as you like. The one rule is that the filename still matches the pattern the project
globs.

## Your own templates

The five templates are functions, and the `templates` key in
[dacha-workbench.config.cjs](/editor/config-reference/#script-templates) replaces any of them.
A project with its own conventions can generate files that already follow them.

## After Create

The editor builds your project's code itself, in watch mode. Writing the file starts a
rebuild, and the spinner in the bottom bar shows it running. When the build finishes, the
editor swaps the new bundle in, drops what it knew about your classes, and reads the
decorators again.

The new class appears in the picker at that point. There is no restart, and nothing to
import by hand.

One side effect is worth knowing. After a rebuild the editor checks the project configuration
against the classes it just read, and repairs anything that no longer matches, such as a field
you renamed. A repair clears the [undo history](/editor/building-a-scene/#undo), because those
older operations no longer describe the project.
